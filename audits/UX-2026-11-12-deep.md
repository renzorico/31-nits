# UX audit: spain-housing-str-analysis  2026-11-12  mode: deep
Commit: 026b187  Auditor model: Opus 5.5 (claude-opus-5-5)  Evidence: screenshots at 1440 (12 screens, dark-only; 02-04 are crops of the left ~1030 px) and 375 (4 screens). Source in site/src and site/index.html. `tsc` and `vite build` were run. No Lighthouse, axe or live browser.

## Verdict
The site is usable. The copy is honest and neutral, every chart states its limits, and there is no critical defect. It is not distinctive. The visual system is the owner's personal-dashboard template (`data-story-design`, from the WhatsApp "Ten years talking" dashboard), copied unchanged onto a contested civic topic. That is most of why it "looks like AI". The biggest issue is fit for the audience, not one bug: Barcelona residents and journalists get an English-only, dark, scroll-jacked slide deck with no byline or date, two different "register" figures, and exact values that are only reachable by hover.

## Defects (Part C)

### [MEDIUM] D-002 No loading state; all text waits for 9 JSON files and a 1.17 MB bundle
- Where: site/src/main.ts:88-101; site/index.html:45-46, 52, 65, 78 … (every `h2` and `.sub` is empty in HTML); site/src/main.ts:22 + mapScreen.ts:3 (MapLibre imported statically); main.ts:117 (map points load at startup); build output: `index-*.js 1,167 KB (325 KB gzip)` plus a 508 KB worker.
- Status: verified in code and build. CWV not measured.
- Standard: CWV (LCP/CLS); Nielsen "visibility of system status"; C4 "works without JS where reasonable".
- Problem: Until every file has loaded, the page shows only the static h1. All 11 screen titles, the lede and the stats are empty, with no placeholder. Link previews, reader mode and no-JS readers get empty headings. The 400 KB map points and the basemap load on page open, even for readers who never reach screen 4. On mobile normal flow, the empty hero stats grow after load, so a layout shift is likely.
- Fix: Put the current English titles and subs in index.html as fallback text, so JS only overwrites them. Load the map with `const { initMapScreen } = await import("./mapScreen")` inside an IntersectionObserver on `#map-screen`. Reserve `min-height` on `#hero-stats`.

### [MEDIUM] D-003 Exact values only on pointer hover; no keyboard or tap path, no tables
- Where: wall.ts:185, price.ts:121, flowsScreen.ts:199, 374, licences.ts:108, hosts.ts:152, rentsScreen.ts:193 (all `pointermove`); DESIGN.md "No tables … exact values live in tooltips".
- Status: verified in code. Touch behaviour suspected: a tap fires pointerdown/up, not pointermove, so most phone taps show nothing.
- Standard: WCAG 2.1.1, 1.3.1; Nielsen "flexibility".
- Problem: The audience is mostly on phones, and journalists need numbers they can copy. The aria-labels give summaries (good), but per-bar and per-quarter values are hover-only.
- Fix: Also bind `click`/`pointerdown` to `showTip`. Add a closed `<details>` "Data" per screen with a small table built from the same arrays. This overrides the template's no-tables rule for this audience.

### [MEDIUM] D-014 Scroll-jacking and fixed-height screens
- Where: story.ts:126-148 (`wheel` + `preventDefault`, one gesture = one screen); styles.css:115-123, 191-194 (`scroll-snap-type: y mandatory`, `.screen { height: calc(100svh - 44px) }`, `.fill { overflow: hidden }`).
- Status: verified in code. Overflow at 900x640, with text zoom, or with ES/CA strings is suspected (not rendered).
- Standard: Nielsen "user control and freedom"; WCAG 1.4.4 / 1.4.10 (content clipped when text grows).
- Problem: Desktop readers cannot scroll partway, skim back or stop between screens. Screens have a fixed height, and `.screen` has no overflow handling. A longer sub, the 3-column rule card (screen 11) or translated text will either clip the chart (`.fill overflow:hidden`) or spill into the next screen.
- Fix: Delete `initPager()` (main.ts:86). Change the snap to `proximity` or remove it. Let screens use `min-height` instead of `height`.

### [MEDIUM] D-015 White text on light series fills fails 4.5:1
- Where: licences.ts:26-30, 113-118; styles.css:151; 1440-dark-07 (e.g. "8%" on grey #8a867c, Mar 2026 row).
- Status: verified (computed).
- Standard: WCAG 1.4.3.
- Problem: 13 px #fff on green #199e70 is about 3.4:1, on violet #9085e9 about 3.1:1, on pink #d55181 about 3.9:1. Ink on "other" #8a867c is about 3.1:1. The 3 px halo does not count toward the ratio.
- Fix: Use `#0b0b0b` text on violet, pink and #8a867c (the skill already does this for amber). Darken green to about #137a57 for white text, or put the label outside the bar.

### [MEDIUM] D-016 Register waffle "not shown" cells are 1.4:1 against the page

### [MEDIUM] D-017 Two different figures for "the register" on one page
- Where: main.ts:56 (hero "10,721 tourist flats on the city's official register" = `register_records`); registerScreen.ts:47 (title "Barcelona's 10,623 tourist-flat licence numbers" = `register_numbers`); register.json `match[-1]`.

### [MEDIUM] D-018 Insider jargon in finding titles

## Owner questions

### Q1. Why it "still looks like AI", and does the style fit?
Specific tells, grouped (evidence above):
1. Type: system SF Pro, heavy, tight-tracked, giant (T-001, T-002). It is the most recognisable AI-landing-page signal and it is on every screen.
2. Hero formula: eyebrow, accent-coloured number, 4-stat row, "SCROLL ↓" (T-006, T-009).
3. Surfaces: near-black page, glowing dots, pill toggles, numbered-circle rail (T-003, T-008, T-011).
4. Rhythm: 11 identical slides, each with a computed two-number sentence as title (T-005, D-018). Titles like "Of Dec 2025's 6,547 month-plus listings, 38% were absent from the Sep 2026 scrape. Of the shorter stays, 22%." read machine-composed because they are templated.
5. No human: no author, date, place or voice in the frame (D-019). The only credit is "GitHub".

Fit judgement (opinion, not scored; the principle is "register must match audience and genre"):
- It does not fit a contested local topic read by Barcelona residents and journalists on phones.
- The dark, cinematic, scroll-snapped register belongs to product launches and personal dashboards. Local civic data journalism uses light pages, editorial type, bylines, dates, sources and citable tables.
- Three verified gaps make it worse for this audience: English-only (`<html lang="en">`), hover-only numbers (D-003), and no byline or date (D-019).
- The neutral copy is the strongest asset. The visual frame undercuts it by looking like a tech showcase.

### Q4. Spanish and Catalan readiness
Where the text lives today:
1. **index.html**: title, meta and OG (6-31), skip link (34), banner (36), eyebrow and h1 (43-44), "Scroll" (47), 9 × "How is this made?", the map "How" paragraph (82-87), method title and sub (185-190), "All caveats and sources" (197).

Cheapest robust path, about 12-16 h total, not for today:
1. Add `site/src/i18n/{types,en,es,ca}.ts`, one typed `Strings` interface of template functions. `tsc` then fails on any missing key, which gives a free parity check.
2. Add `site/src/format.ts` built on `Intl.NumberFormat`, `Intl.DateTimeFormat` and `Intl.PluralRules`, with the locale read from `document.documentElement.lang`. Separate data keys from display labels.
3. Build three static entries (`/`, `/es/`, `/ca/`) by extending the existing `transformIndexHtml` plugin (vite.config.ts:14-19), each with its own `lang`, meta and `hreflang` alternates. Switch fetches to `import.meta.env.BASE_URL + "data/"`. Use plain EN · ES · CA links in the banner.
4. In `src/config.py`, store lever texts as `{"en","es","ca"}`. Export them, and assert all three per field in `tests/test_export.py`.
5. Fix a neutral glossary before translating: HUT / habitatge d'ús turístic / vivienda de uso turístico; lloguer / alquiler de temporada; estada / estancia mínima. Keep laws under their official titles. Have a native speaker review the legal lines.
